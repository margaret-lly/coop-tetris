# 前端代码说明（交给别的设计工具 / 人改之前先看这页）

## 目录

| 文件 | 作用 | 改不改 |
| --- | --- | --- |
| `设计预览-单文件.html` | 单文件预览版：CSS 已内联、棋盘用假数据画满、右下角可切「主页 / 游戏页」，**双击就能在浏览器打开，不需要服务器** | 直接拿去改最省事 |
| `index.html` | 真实页面的结构（主页 `#home` + 游戏页 `#game`） | 可以改结构，但要保住下面的 id |
| `style.css` | 全部样式（淡紫白主题、云朵、装饰、卡片、棋盘） | **重做视觉基本只改这个** |
| `skin.js` | 皮肤配置：七种方块颜色、两位玩家的头像/名字 | 可以改 |
| `game.js` | 渲染 + 键盘 + 联机通信 | **不要改逻辑** |
| `assets/` | 角色图（透明底 webp） + 两个脸部头像 | 换图直接替换同名文件 |

## 只要保住这些 id，换皮不会坏

主页：`name-input`、`create-btn`、`code-input`、`join-btn`、`home-msg`

游戏页：`room-code`、`players`、`score`、`lines`、`turn-badge`、`board`、`over`、`over-stat`

`game.js` 还会用到这几个 class 名：`.cell`（棋盘格，落块时加 `.filled`）、`.player`、`.avatar`、`.meta`、`.hidden`

棋盘尺寸写死在 `style.css` 里：`.board` 是 `repeat(10, 30px) × repeat(20, 30px)`，格子总数必须正好 200 个（10 列 × 20 行），否则 `game.js` 画不进去。

## 联机和后端的关系

- 棋盘、消行、得分、回合**全部由服务端算**，前端只负责画和按键。
- 前端只发这几种操作：`join_room`、`left`、`right`、`down`、`rotate`、`hard`；收到 `room_state` 后整屏重画。
- 建房走 `POST /api/rooms`，查房走 `GET /api/rooms/:code`。
- 所以：**改造视觉时不要动这套 id / class / 数据流**，否则接不回 `server.js`。

## 只想要视觉、不想要联机

用 `设计预览-单文件.html` 就够了：里面没有任何网络请求，棋盘是写死的假数据，随便改 HTML 和 CSS，浏览器双击即可看到效果。改满意之后，再把对应的 CSS/结构搬回 `style.css` 和 `index.html`。
